## G 值算法重做（v7.14.0，仅 185b）

用户问"有没有看过 github 上其他项目怎么优化算法，精度准确性还是不够"。
之前只参考了 chrono-g 的**画面**，没看算法。这次真去读了源码：

**参考项目结论**
- `TioRuben/chrono-g`：`g_meter.c` 显示的就是 `imu.c` 里的 `ema_state.accel_x`（**单轴载荷系数**，
  飞机过载表），不是摩托车侧向 G。可借鉴的只有：片上 LPF、gyro 零偏 5000 样本平均、
  UI 只在 |Δ|≥0.05 时重画。
- `a-nico/MotorcycleLean`：`g = 100*az/G` 也是显示 az（法向载荷），S=sqrt(ax²+ay²-G²) 是"侧滑"指示，
  不是稳态侧向 G。参考价值有限。
- `upiir/gforce_meter_gauge_esp32_nextion`、`PierreVerbe/Leanometer`：纯原始轴，无去重力、无融合。
- **`d3sd1/gnss-imu-lean-angle-lstm`（Measurement 期刊论文配套代码）** 才是关键。它的
  `simulate.py` 传感器模型：
      a_cent = v²·tan(φ)/L ;  a_y = a_cent·cos φ − g·sin φ ;  a_z = a_cent·sin φ + g·cos φ
  稳态压弯 a_cent = g·tan φ 代入 → **a_y ≡ 0、a_z = g/cos φ**。
  即加速度计在稳态压弯时**读不到任何倾角信息**，只有合力大小 |f| = g/cos φ 有用。
  它的 CF 基线用 `phi_obs = atan(v·ω_z/g)`（车速 × 陀螺偏航率），完全绕开这个死结。

**诊断出的 5 个 bug（都在 boards/185b/MotoNav/MotoNav.cpp）**
1. **滤波系数没按 dt 归一**：imuTick 跑在 kHz 级主循环里，`accelWeight=0.04` 每毫秒修正一次，
   等效时间常数只有 25ms → 压弯时 roll 被加速度计瞬间拉回 0。这是最致命的。
2. **稳态压弯时 atan2(ay,az) 恒等于 0**，旧代码据此反旋加速度 → yLat≈0 → 屏幕永远 0.00G。
   旧代码那个 `arCorr` 补偿算的是 `ay·cos(roll) − az·sin(roll)`，压弯时 ay=0、roll≈0，
   补偿量也是 0，等于没生效。
3. `imuLinearG = |imuG − 1|` 错，应为 `sqrt(imuG² − 1)`；45° 时 0.414 vs 1.0，差 59%。
4. gyro 零偏只用 **8 个样本**平均（chrono-g 用 5000），残差 ~0.3dps，一分钟漂 18°。
5. 显示 2 位小数（10mg）但没做死区/滞环，末位一直抖。

**改法**
- imuTick 采样节流到 8ms（≈125Hz，ODR 112Hz），所有系数改 `dt/(tau+dt)`。
- roll：陀螺积分给高频；加速度只给 **|φ| = atan(sqrt(|f|²−1−lon²))**（稳态压弯精确、零漂），
  符号用陀螺积分带 3° 滞环（`imuLeanSign`）。6° 起信、18° 全信；|lon|>0.2g 时降权（刹车会被误判成压弯）。
  静止直立时 2s 时间常数归零，压住残余漂移。
- 侧向 G：`sqrt(|f|²−1−lon²)`（= tan φ），|lon| 大时切到 `tan(φ)`；纵向 G 用 `ax·cosθ+az·sinθ` 去重力。
  都在 imuTick 里 90ms EMA，drawImuPage 只读。
- gyro 零偏累计到 400 样本（3.6s）取平均，32 个之后就开始用。
- 静止判据 0.15g/3dps → 0.05g/2dps（旧门限会把 25° 压弯当静止）。
- 片上 LPF：accel MODE_1(3.63%≈4Hz)、gyro MODE_3(13.37%≈15Hz)。
- 显示加 0.02G 死区 + 0.006 滞环。
- `G_LEAN_SIGN` 宏（默认 1.0f）：上车后若倾角/侧向 G 方向反了改 -1.0f。

**验证**：写了 `docs/g_algo_sim.py`，用论文的传感器模型 + QMI8658 噪声（4mg/0.06dps）跑
15/30/45/55° 弯 + 1.0g 刹车，同一份数据喂新旧两套算法：
- 旧：15°读0.04(真0.27)、30°读0.11(真0.58)、45°读0.22(真1.00)、55°读0.34(真1.43)，**-77%~-85%**
- 新：四档误差都 <0.01G，弯内抖动 0.014~0.040G pk-pk
图：`docs/g_algo_compare.png`（SVG 版同名 .svg）。`pio run -e esp32s3-185b` SUCCESS。

## v7.14.3 — G 值球方向全错（只往 RIGHT 走）的根因：车身坐标轴映射差了 90°

**现象**：球只会往 RIGHT 方向动，前进后退都一样。

**根因（两处，同一个错误）**
1. 旧代码按 "IMU X=车身前、Y=侧、Z=上" 写：`ar=atan2(ay,az)`、`lonNow = ax·cosθ + az·sinθ`。
   实际安装是**屏幕朝上、屏幕顶边朝车头**（G 页 FRONT 画在顶上，用户就这么读），QMI8658 跟屏幕对齐：
   **IMU X=车身右、Y=车身前、Z=车身上**。于是纵向加速度整个落在 ay，`lonNow=ax≈0` 减不掉它，
   全被 `latSq = |f|²-1-lon²` 当成横向。
2. 陀螺同样错位：`imuRoll += wx·dt` 积的是**俯仰率**（≈0），所以压弯时 `imuRoll` 恒为 0，
   `imuLeanSign` 永远学不到 -1，横向 G 恒为正。加上第 1 条的 `sqrt()` 永远为正 →
   **球只往右，前进后退都一样**。

**修法**：显式写出车身坐标映射 `ImuMount {right, fwd, up, sr, sf, su}` + `imuToBody()`，

- **pitch 门限也修了**：旧 `pTrust = 1-|f|-1/0.15` 在 0.3g 加速时还有 0.7 权重，而 `ap` 此时

## v7.14.4 — 球不往左右动：wA 的判据选错了对象

**现象**：v7.14.3 之后前后方向对了，但球完全不往 LEFT/RIGHT 动。

**根因**：`latA = sqrt(|f|²-1-lon²)` 有个盲区 —— **静止倾斜时它恒等于 0**。
静止时 |f| 恒为 1g（不管车身怎么歪），所以 latSq = 1-1-0 = 0。物理上没错
（静态倾斜确实没有横向加速度），但用户侧倾车身 / 在桌上把板子歪一下，球就一动不动。
本来有 `latB = tan(roll)` 做兜底，可切换权重 `wA` 用的是 `|lonNow|`（纵向加速）——
静止倾斜时 lonNow≈0 → wA=1 → **永远只用 latA=0，latB 一次都没用上**。判据选错了对象。

**修法**：wA 改成看 `|f|` 偏离 1g 的多少：
```
wA  = constrain((imuG - 1.0f) / 0.03f, 0, 1);          // |f|>1.03 才完全信实测 latA
wA *= constrain(1 - (|lonNow|-0.20)/0.25, 0, 1);       // 纵向加速大时 lonNow 不可靠（保留）
latRaw = (wA*latA + (1-wA)*|latB|*bTrust) * imuLeanSign * G_LEAN_SIGN
bTrust = constrain((|imuRoll| - 1.0f)/2.0f, 0, 1)      // 3° 以下降权，防直线微摆抖动
```
- 稳态压弯时 latA = latB = tanφ，两者完全相等 → **切换不影响压弯精度**
- 差别只在"静止倾斜"这一档：v7.14.3 显示 0，v7.14.4 显示 tanφ
- bTrust 只在 1°~3° 生效（对应 0.017~0.052G），压弯和桌面测试都不受影响

**验证**（`docs/g_axis_check.py` 加 E 段，`lat_world=0` 模拟静止倾斜）：
| 倾角 | latA | latB | v7.14.3 球 | v7.14.4 球 |
|---|---|---|---|---|
| -45° | 0.000 | -1.000 | 不动 | LEFT |
| -30° | 0.000 | -0.577 | 不动 | LEFT |
| +30° | 0.000 | +0.577 | 不动 | RIGHT |
| +45° | 0.000 | +1.000 | 不动 | RIGHT |

A~D 段（直线加减速、稳态压弯、压弯+加速、安装俯仰）结果与 v7.14.3 完全一致，无回归。

**副作用（已知、可接受）**：车停在侧架上斜着 15° 时，G 会显示 0.27G。原因是静止倾斜
和侧架停放物理上完全无法区分（都是 |f|=1g + 有倾角）。真压弯时 |f|=1/cosφ>1，两者才分开。
摩托车 G 表普遍就是拿 tan(lean) 当侧向 G 显示，可以接受。

**改动**：`MotoNav.cpp`（→ v7.14.4-185B）、`docs/g_axis_check.py`（加 E 段 + bTrust）。

## v7.14.5 — 静止 G 显示 1.3：latB 用了绝对倾角，LEAN 用的是相对倾角

**现象**：v7.14.4 之后球死死顶在 RIGHT，静止时 G 显示 1.3 几。

**推断**：`1.3 ≈ tan(52.4°)`。v7.14.4 里 `latB = tan(imuRoll)` 用的是**绝对**倾角，
而屏幕上 LEAN 显示的是 `imuRoll − imuBiasRoll`（相对）。两者不一致：
只要板子有横滚偏置、或用户点屏归过零，LEAN 显示 0.0 而球按绝对倾角跑。
`latA` 在静止时恒为 0，v7.14.4 又把权重全给了 latB，所以这个偏置直接暴露成 G=1.3。

**修法**：`rollRel = imuWrap180(imuRoll - imuBiasRoll)`，latB / bTrust 都用 rollRel。
屏幕上两个数字（LEAN 和 G）从此来自同一个角度。

**调试加码**：`IMU_SHOW_AXES` 现在打两行小字（cyG+168 / cyG+180）：
```
F+0.00 R-0.79 U+0.61     ← 车身坐标比力
RLL +52.4 LATB+1.28      ← 相对倾角、tan(相对倾角)
```
判读：
- R≈0.00 / U≈1.00 / RLL≈0   → 安装正常，问题在别处（漂移或初始化）
- R≈-0.79 / U≈0.61 / RLL≈52 → 板子真的横滚了 52°（安装角度，或手持姿态）
- RLL≈52 但 LEAN 显示 0.0   → imuBiasRoll 被点屏归过零，v7.14.5 之后两者会一致
